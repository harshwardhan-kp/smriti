ABSOLUTE RULES

1. NO LITERAL COLOURS. Not one `Color(0xFF...)` may survive in the file you are editing. Every
   screen currently declares its own private `ColorAmber` / `ColorInk` / `ColorCream` /
   `ColorCardBg` / `ColorChipBg` / `ColorRedAlert` at the top — DELETE those declarations and
   replace every use with a member of `S`. The mapping is fixed:
       ColorInk        (was the near-black page)  -> S.Paper        [the page is now near-white]
       ColorCream      (was the light type)       -> S.Ink          [type is now near-black]
       ColorCream@0.6  (was muted type)           -> S.Muted
       ColorCream@0.45 (was faintest type)        -> S.MutedSoft
       ColorCardBg / ColorChipBg (dark cards)     -> S.PaperSunk
       ColorAmber      (was the accent)           -> S.Red          [the accent is now red]
       ColorRedAlert   (was the live/overdue red) -> S.Red
       a "still working" state                    -> S.Amber
       a "done / settled" state                   -> S.Green
       any border or divider                      -> S.Hairline

2. NO LITERAL TEXT STYLES. No `fontSize =`, no `fontFamily =`, no `MaterialTheme.typography.*`,
   no `fontWeight =` except where a SmritiType style already carries it. Every Text() gets
   `style = SmritiType.<something>`. The mapping is fixed:
       a screen's own title / a record's title  -> SmritiType.DisplaySmall  (Instrument Serif)
       a card title                             -> SmritiType.Title
       prose, summaries                         -> SmritiType.Body
       a card's supporting line                 -> SmritiType.BodySmall
       a control's sans label                   -> SmritiType.Label
       timestamps, tags, counts, states         -> SmritiType.Meta / MetaMedium
       any button label                         -> handled by SmritiButton, do not style it
       transcripts and OCR output               -> SmritiType.Mono

3. EVERY PIECE OF UI COPY IS LOWERCASE. Every string on antimattr.one is lowercase, including
   its own name. "Timeline" becomes "timeline". "Open tasks" becomes "open tasks". "Could not
   extract" becomes "could not extract". This applies to headings, labels, buttons, empty
   states, placeholders and content descriptions' visible counterparts. It does NOT apply to
   user data (a transcript, a person's name, a title the model wrote) — never lowercase what a
   person said or wrote. It does not apply to contentDescription strings, which are for a
   screen reader and should stay ordinary sentence case.

4. NO LITERAL SPACING. Use S.xs (4), S.sm (6), S.md (10), S.gutter (16), S.lg (24), S.xl (32),
   S.section (44). Horizontal page padding is S.gutter and nothing else.

5. NO LITERAL RADII. Use S.r6 (the default — use this unless told otherwise), S.r8, S.r24,
   S.pill. 12.dp and 16.dp corners are gone from this app.

6. NO ELEVATION, NO SHADOWS. This language is drawn, not stacked. A card is separated by a
   hairline border and a background one step back (S.PaperSunk), never by a shadow. If a
   Material component insists on elevation, set it to 0.dp.

7. Metadata wears brackets. Any small mono fact — a timestamp, a state, a count, a due date —
   goes through `BracketLabel("...")`, which renders `[label]` with the brackets in red. Do not
   hand-write square brackets into a string; call the component.

WHAT NOT TO BREAK

You are changing appearance ONLY. Do not change any of the following, in any file:
  - navigation, callbacks, or the shape of any function's parameters
  - ViewModels, DAOs, Flows, or anything that reads or writes the database
  - which composable is rendered for which enrichmentState
  - LazyColumn item keys (they are prefixed "task-" / "record-" to stop a key collision that

  - the try/catch around BitmapFactory.decodeFile, or the branch that renders a mic glyph when
    record.photoPath is blank (that is how a voice-only memory is drawn)
  - any contentDescription that already exists

THE EXACT PUBLIC API — the call site is already being written against this signature, so it

    fun PhotoViewer(
        photoPath: String,
        onDismiss: () -> Unit
    )

WHY THIS EXISTS
Opening a memory shows its photograph in a small box and there is no way to see it properly.
A camera capture is 4096x3072; a bubble capture is a full screenshot at the phone's own aspect
ratio. Both are currently shown cropped into a 4:3 frame and neither can be opened.

BEHAVIOUR

1. It is a full-screen overlay above everything, including the Scaffold and its top bar. Use
       Dialog(
           onDismissRequest = onDismiss,
           properties = DialogProperties(usePlatformDefaultWidth = false)
       )
   `usePlatformDefaultWidth = false` is what lets it fill the screen; without it Android insets
   the dialog and you get a small box, which is the bug we are fixing.

2. Background: S.InkDeep, fillMaxSize. A photo is judged against black, not against paper, and
   this is the one screen in the app allowed to be dark for that reason.

3. THE IMAGE IS NEVER CROPPED. `contentScale = ContentScale.Fit` and nothing else. Do not use
   Crop, do not use FillBounds, do not impose an aspectRatio modifier. Fit is the whole point of
   the task: the picture appears at its true proportions, letterboxed against the black if it
   does not match the screen.

4. DECODING. Do not call BitmapFactory.decodeFile(path) bare. A 4096x3072 JPEG decodes to about
   50 MB as ARGB_8888 and this app already runs a 4 GB language model on the same device.
   Two-pass decode inside a `remember(photoPath)`:
       - first pass with `BitmapFactory.Options().apply { inJustDecodeBounds = true }` to read
         outWidth/outHeight without allocating
       - compute inSampleSize as the largest power of two that keeps both dimensions >= 2048
       - second pass with that inSampleSize to get the bitmap
   2048 is generous enough that zooming in still looks sharp on a 1440-wide screen. Wrap the
   whole thing in try/catch and hold `ImageBitmap?`; if it comes back null, show a centred
   `BracketLabel("could not open the photo")` and nothing else.

5. ZOOM AND PAN. Hold `var scale by remember { mutableStateOf(1f) }` and
   `var offset by remember { mutableStateOf(Offset.Zero) }`, applied with
   `Modifier.graphicsLayer(scaleX = scale, scaleY = scale, translationX = offset.x, translationY = offset.y)`.
       - pinch: `Modifier.pointerInput(Unit) { detectTransformGestures { _, pan, zoom, _ -> ... } }`
         with `scale = (scale * zoom).coerceIn(1f, 5f)` and `offset += pan`
       - when scale returns to 1f, snap offset back to Offset.Zero, or the picture stays stranded
         off-centre with no way to recover it
       - clamp the offset so the image cannot be flung off screen: bound each axis to
         `±(size * (scale - 1f) / 2f)` using the measured size from `Modifier.onSizeChanged`
       - double tap toggles between 1f and 2.5f, resetting offset to Offset.Zero on the way back
         down. Use a second `pointerInput` with `detectTapGestures(onDoubleTap = ..., onTap = ...)`
       - single tap dismisses ONLY when scale is 1f. Tapping while zoomed in must do nothing —
         someone inspecting a receipt should not lose their place by touching the screen.

6. A close control: `Icons.Default.Close` in an IconButton, top-end, inside
   `Modifier.statusBarsPadding().padding(S.gutter)`, tinted S.OnDark, contentDescription "Close",
   onClick = onDismiss. The system back button already dismisses via the Dialog's
   onDismissRequest — do not add a BackHandler.

7. Bottom-centre, above the navigation bar, show the picture's real dimensions in the app's own
   metadata language:
       BracketLabel("${bitmap.width} × ${bitmap.height}", labelColor = S.OnDark.copy(alpha = 0.6f))
   inside `Modifier.navigationBarsPadding().padding(S.gutter)`. Use the DECODED bitmap's
   dimensions, and note in your summary that these are post-downsample and therefore smaller
   than the file on disk — that is acceptable and honest for what it is.
