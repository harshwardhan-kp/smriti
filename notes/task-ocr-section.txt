DESIGN INTENT — read carefully, this is the whole point
OCR was removed from the capture path earlier today because it blocked the user and its output
was fused into the language-model prompt. It comes back now under two hard rules:

  RULE 1: OCR NEVER runs on the capture path. The user must still see photo + transcript in
          ~1.4 s. OCR happens only inside the background enrichment pass.
  RULE 2: OCR text is its OWN section. It is stored in its own column and is NOT passed to
          Extractor, NOT concatenated into any prompt, and NOT used to build the title or
          summary. It exists as independent data for future features (search over photographed
          text, evidence display, cross-checking a vision model later).

If you fuse OCR back into the extraction prompt you have defeated the purpose of this task.
