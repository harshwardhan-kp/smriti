Fix which action a stated deadline is attached to. Edit files directly.

THE DEFECT (verified on device 2026-09-05)
Transcript: "Rohit ships the API by Friday and we need two hundred more units from Sharma Traders"
Extracted actions: "Rohit ships the API" and "Need two hundred units from Sharma Traders".
BOTH are given due = 2026-09-11.

The first is correct - "by Friday" belongs to it. The second is wrong: nothing in that clause
states a deadline. The date is right; the ATTRIBUTION is wrong.

Cause: DueDateResolver.resolve() builds its haystack as `actionText + " " + transcript`. The
transcript contains "friday", so every action finds a temporal expression regardless of whether
the deadline belongs to it. That was a design error in the original spec.

REQUIRED CHANGE - app/src/main/java/com/smriti/app/ai/DueDateResolver.kt

Attribute a temporal expression to the action it actually belongs to, by clause:

  1. If the ACTION TEXT itself contains a temporal expression, resolve from that alone.
     Done - no transcript involved.
  2. Otherwise split the transcript into clauses on ",", ";", " and ", " then ", " after that ".
     Keep them in order. Lowercase for matching.
  3. Find the clause(s) containing a temporal expression. If there are none -> null.
  4. Pick the clause whose words overlap the action text most (case-insensitive word-set
     intersection, ignoring stop words: the, a, an, to, of, for, from, we, i, you, it, and,
     more, need, needs, by, is, are, be). Require the BEST overlap to be at least 1 real word.
  5. If the winning clause contains a temporal expression -> resolve from that clause.
     If the winning clause does NOT -> return null. This is the fix: the units clause wins
     nothing from the friday clause.
  6. If two clauses tie on overlap, return null - ambiguous attribution must not invent a date.

Keep every existing rule after attribution EXACTLY as it is: weekday computed with
TemporalAdjusters.next() ignoring the model's value, today/tonight/tomorrow/day-after-tomorrow,
the ISO-8601-only acceptance for anything else, and the two-year range guard.

Change the signature to make the clause logic testable:
    fun resolve(actionText: String, transcript: String, modelDue: String?, today: LocalDate): String?
stays as-is, but extract the attribution into an internal function so tests can hit it directly.
